# TAGTAG 开发现状与需求校对草案

> 实现状态说明（2026-08-11）：本文第 1、2、7 节保留了原型审计时的历史快照，不再代表当前代码状态。受管存储、SQLite 元数据、Windows 系统入口、一致性处理、退出管理、全局备份恢复和文件夹标签动态子项继承现已实现；当前能力以 README、本地 `.scratch/` 工单和自动化测试为准。

> 状态：待用户确认，不是已冻结需求。
> 审计日期：2026-08-09。

## 1. 结论

当前项目完成的是一个可构建、可持久化的 **Flutter Windows 标签语义原型**，不是产品方案中定义的完整 Windows MVP。

原型已经证明以下核心模型可以工作：标签实体与标签位置分离、同一标签出现在多条路径、独立同名标签、资源多标签、父子标签同时直接标注、多空间最小切换和 JSON 往返。

用户已校正存储方向：TAGTAG 不是原地索引器，而是必须先初始化存储根目录，再将外部资源默认复制、可选移动到受管存储中的资料库。当前原型只保存任意路径字符串，与这一核心工作流不一致。

真实资源导入、文件打开与定位、Windows 全局快捷键、Explorer 右键、文件监控、SQLite、继承标签、组合检索、空间级可靠备份与迁移都尚未完成。后续开发前还必须校正若干关键语义，否则继续叠加功能会把原型假设固化为产品约束。

## 3. 原始 15 项需求对照

| # | 原始需求 | 当前统一理解 | 当前实现 | 校对结论 |
|---|---|---|---|---|
| 1 | 文件和文件夹统一打标签 | “文件”包含文件夹；软件必须先初始化存储根，再把资源默认复制、可选移动到受管存储 | 只有手工资源记录 | 当前实现方向不符 |
| 2 | 后台全局快捷键打标签 | 应用隐藏时唤起 Quick Tag，并明确展示目标对象 | 仅窗口聚焦时生效 | 未实现；目标对象来源待确认 |
| 3 | Explorer 右键打标签 | Explorer 单选/多选调用 TAGTAG Quick Tag | 无 | 未实现；建议首版只提供一个稳定入口 |
| 4 | 标签交叉、多选、重名且可靠区分 | 唯一标签的多个位置共享一个实体和资源集合；非唯一情况下，同名位置对应不同实体并完全隔离 | 模型能表示实体与位置，但当前筛选统一按位置 | 数据结构部分满足，浏览语义不满足 |
| 5 | 类似 Explorer 的浏览组织界面 | 浏览受管存储中的唯一实体，并通过标签/索引关系形成虚拟组织视图 | 只有 Explorer 风格布局，没有真实受管目录导航 | 部分；“长得像”不等于“工作流等价” |
| 6 | 一个对象有多个标签 | 一个资源可有多个直接标注 | 已支持 | 已验证 |
| 7 | 一个对象同时标 A 与 A/B | 父位置与子位置是两个可并存的直接标注 | 已支持并去重完全相同标注 | 已验证 |
| 8 | A/B/C 与 D/F/C；C 可相同也可不同 | 若 C 唯一，两条路径共享同一实体，任一路径自动显示其全部资源；若 C 非唯一，则是两个仅同名的独立实体，资源不互通 | 可创建共享实体或独立同名实体，但默认浏览仍按具体位置隔离 | 模型部分验证，唯一标签浏览行为需重做 |
| 9 | 标签层级近似无上限 | 不设产品层数限制，但必须防循环并懒加载 | 数据结构可递归，未做深度/性能验证 | 部分 |
| 10 | 浏览结果与标签层级关联 | 可按具体位置、同一实体、是否含后代筛选 | 只有具体位置 + 是否含后代 | 部分 |
| 11 | 标签新增、修改、删除 | 分清标签实体、标签位置和删除子树；位置删除默认提升子项；实体删除移除其全部位置、标注和继承规则，但不触碰资源 | 可新建/复用位置、改实体、删位置子树 | 业务语义已确认，实现需重做 |
| 12 | 清标签后恢复原位置 | 清标签只删除关系；资源仍在待整理区受管。用户也可显式选择退出管理：恢复先前路径、移动到指定位置或按平台规则删除 | 普通操作只改 JSON；无真实导入、退出管理、日志或撤销 | 业务语义已确认，未实现 |
| 13 | 检索机制 | 首版检索名称、受管路径、标签和基础元数据，支持标签布尔条件；不读取或索引正文 | 仅名称/路径子串和单标签过滤 | 部分 |
| 14 | 最近项目和常用标签 | 基于应用行为事件计算，并与文件修改时间区分 | 简单实现；最近列表未按事件时间排序 | 部分且有偏差 |
| 15 | 多空间、备份、迁移 | 一个全局存储根；空间隔离标签、查询和历史，但可共享同一受管实体；支持全局与空间级迁移 | 多空间共用一个 JSON；整应用 JSON 备份 | 空间模型已确认，备份边界待确认 |

## 4. 建议冻结的领域术语

已确认的术语已写入根目录 `CONTEXT.md`；尚未确认的标签语义继续保留为建议稿：

| 术语 | 建议定义 | 明确不表示 |
|---|---|---|
| 资源 | TAGTAG 管理的文件或文件夹 | 只表示普通文件 |
| 逻辑资源 | 与存储根中的一个具体文件或文件夹对应，具有稳定身份、名称、路径、空间和标签关系 | 标签引用或按内容摘要合并的共享对象 |
| 存储根目录 | 初始化时必须指定、用于保存全部受管资源的全局唯一路径 | 可选索引目录或空间目录 |
| 导入 | 默认复制、可选移动外部资源到存储根目录 | 仅登记外部路径 |
| 导入并标注 | 在同一确认窗口选择复制/移动和可为空的标签集合；零标签进入待整理区，取消则不产生任何导入结果 | 两段式导入和标签弹窗 |
| 外部源资源 | 复制导入后留在原处、但不再由 TAGTAG 跟踪或同步的原资源 | 受管版本或同步副本 |
| 受管实体 | TAGTAG 管理范围内的逻辑资源记录，与存储根中的一个具体文件或文件夹对应 | 每个标签路径下的副本或按内容合并的共享对象 |
| 受管路径 | 资源在存储根内的持久 Windows 普通文件或文件夹位置，可直接打开和编辑；名称冲突按同一父目录和当前操作系统规则判断 | 标签层级路径、临时工作副本或全局唯一名称 |
| 资源文件本体 | 存储根中的原始、未加密 Windows 普通文件或文件夹；数据库只记录元数据和索引 | 数据库 BLOB、加密容器或应用专用文件包 |
| 存储投影 | 首版不使用虚拟文件系统；每个受管实体对应一个持久的 Windows 普通文件或文件夹，其他组织位置使用数据库索引，必要时使用快捷方式或链接 | 每个标签位置复制一份文件 |
| 导入目标文件夹 | 导入窗口中选择的存储根内物理目录；文件夹导入保留完整内部层级 | 标签路径或存储根外目录 |
| 虚拟引用 | 标签或组织视图到受管实体的逻辑关系 | 必须落盘的快捷方式或链接文件 |
| 标签空间 | 全局存储根之上的独立标签、查询和历史视图，可跨空间引用同一受管实体 | 独立物理资料库或存储目录 |
| 空间成员关系 | 受管实体属于某个标签空间的事实，与该空间标签标注独立；可属于多个空间 | 标签关系或物理副本 |
| 全局备份 | 数据库、全部受管资源、操作日志、清单和校验信息组成的完整恢复单元 | 仅元数据导出 |
| 空间导出包 | 单个空间的标签、查询、历史、资源清单及其引用资源内容组成的迁移单元 | 全局备份或无内容模板 |
| 空间模板 | 只含标签结构等配置、不含资源内容的初始化材料 | 备份 |
| 标签实体 | 有稳定身份的概念标签，名称不作为身份 | 标签树中的某一条路径 |
| 标签位置 | 标签实体在标签层级中的一次出现 | 新的独立标签实体 |
| 删除标签位置 | 只删除一次层级出现；子位置默认提升，其他位置和资源标注保留；最后一个位置转入实体删除确认 | 默认删除子树、资源或整个实体 |
| 删除标签实体 | 删除当前空间中该实体的全部位置、直接标注和继承规则；子位置提升，资源及空间成员关系保留 | 删除资源、退出管理或级联删除子标签实体 |
| 唯一标签 | 多个位置共享同一标签实体和资源集合，任一路径浏览结果一致 | 名称碰巧相同的独立标签 |
| 独立同名标签 | 名称相同但身份和资源集合互相独立的标签实体；新建默认不唯一 | 唯一标签的多个位置 |
| 合并标签 | 显式把独立标签合并成唯一标签，执行前展示资源与层级影响 | 按名称自动合并 |
| 拆分标签 | 显式把唯一标签的部分位置拆成独立实体，执行前展示资源与层级影响 | 普通位置复制 |
| 直接标注 | 用户明确建立的资源与标签实体关系，不随物理父目录变化 | 继承或查询结果 |
| 子项继承 | 文件夹标签显式启用的动态规则，当前及未来子项获得有效标签，移出后失去 | 批量直接标注 |
| 有效标签 | 直接标注与当前继承结果的合集，并保留来源 | 全部写成直接标签 |
| 操作日志 | 记录导入、移动、改名等物理变化并支持撤销 | 最近使用记录 |
| 未标注资源 | 没有标签但仍由 TAGTAG 管理的资源 | 孤立或未管理文件 |
| 待整理区 | 显示属于当前空间但在该空间没有有效标签的资源 | 回收站或异常列表 |
| 全局待整理 | 显示在所有空间中都没有有效标签的受管实体 | 当前空间待整理区 |
| 孤立内容 | 存储根中有物理内容、数据库却没有受管实体记录的异常 | 合法的未标注资源 |
| 接管 | 为存储根中的孤立内容建立受管实体记录 | 再复制一份文件 |
| 缺失资源 | 数据库仍有受管实体记录、物理内容却不存在的异常 | 正常退出管理 |
| 一致性告警 | 存储根物理状态与 TAGTAG 记录不一致时产生的待处理告警 | 普通使用通知 |
| 退出管理 | 将资源恢复到先前路径、移动到指定位置或按平台规则删除 | 清空标签 |

## 5. 建议的产品需求基线

### P0：先形成可日常使用的 Windows 核心

1. 首次使用必须初始化一个有效、可写的全局存储根目录；未完成初始化时只允许进入初始化流程。
2. 将文件和文件夹统一作为资源导入；默认复制到存储根目录，也可通过设置选择移动。
3. 复制导入是一次性边界：外部源资源保留但不再跟踪或同步，存储根内版本成为唯一受管实体。
4. 每个受管实体对应存储根中的一个具体文件或文件夹；标签层级和多处展示默认只保存数据库索引，必要时可建立快捷方式或链接，但绝不为同一受管实体复制文件。
5. 首版不实现全局内容寻址、透明去重、内容对象共享或写时复制；即使文件内容相同，只要是不同物理路径就作为不同受管实体。资源文件必须保持为存储根中的原始、未加密 Windows 普通文件，编辑始终直接作用于该具体文件；严禁将文件字节保存为数据库 BLOB、加密容器或应用专用包。
6. 默认保留原文件名，标签操作不改名；只有显式改名或启用命名规则才能修改名称，且所有改名写日志并支持撤销。
7. 名称冲突遵循当前操作系统规则，唯一性只约束同一父目录；不同文件夹允许同名，同目录冲突不得自动覆盖。
8. 导入并标注窗口必须允许选择存储根本身、已有子文件夹或现场新建子文件夹；默认目标可配置，未配置时使用存储根。
9. 导入文件夹时保留该文件夹本身及完整内部层级；导入多个文件时保留各自名称。目标不得位于全局存储根之外，标签操作不改变目标目录。
10. 清空标签只删除标签关系，资源继续受管并进入待整理区；清标签界面可进一步显式选择退出管理。
11. 退出管理提供三种方式：恢复到先前路径、移动到指定位置、按当前平台规则删除；Windows 首版删除到回收站。
12. 空间成员关系与标签关系分离；资源加入空间后即使零标签也仍属于该空间，同一受管实体可属于多个空间。
13. 空间待整理区显示属于当前空间但在该空间无有效标签的资源；即使它在其他空间有标签，也仍可出现在当前空间待整理区。
14. 全局待整理视图只显示在所有空间中都没有有效标签的资源；不属于某空间的资源不出现在该空间待整理区。
15. 持续监控存储根目录的结构变化；非 TAGTAG 操作导致记录与物理状态不一致时产生一致性告警。
16. 发现新增孤立内容时，让用户选择接管为受管实体或移动到存储根之外；不静默接管，也不自动删除。
17. 发现受管实体被外部删除时，标记为缺失资源并告警；保留标签、历史和原路径，直到用户重新定位或清除记录。
18. 发现存储根内的外部改名或移动时，识别同一实体并告警，让用户选择接受新路径或恢复记录路径。
19. 正常编辑软件造成的内容和时间戳变化只刷新元数据，不产生一致性告警。
20. 资源可真实打开、在 Explorer 中定位；受管存储内的外部结构变更能被识别并进入核对流程。
21. 标签实体与位置分离；新建标签默认不唯一，同名也创建独立实体；用户显式复用当前空间已有标签时，唯一标签的多个位置共享同一资源集合。
22. 唯一性不通过普通开关改变；已有标签只能通过显式合并或拆分调整身份关系。删除普通标签位置只移除该位置并默认将子位置提升到其父级，保留其他位置及资源标注；最后一个位置必须转入标签实体删除确认。“删除子树”作为独立命令。删除标签实体会删除当前空间中的全部位置、直接标注和继承规则，子位置提升，但资源文件和空间成员关系保持不变，失去最后一个有效标签的资源进入空间待整理区。所有高影响操作执行前展示资源与层级影响，写入日志并支持撤销。
23. 给文件夹打标签默认只建立文件夹自身的直接标注；用户可显式启用动态子项继承，使当前和未来子项获得有效标签，移出后自动失去。
24. 继承结果不写成子项直接标签，界面必须显示继承来源；“批量直接标注当前子项”作为独立命令提供固定结果。
25. 提供受管目录视图与标签虚拟视图；列表分页/虚拟化，标签筛选支持位置、实体和包含后代。
26. SQLite 只保存配置、资源路径、标签、索引、日志和一致性状态等元数据，使用串行写入边界并具备 schema version、约束、事务和可恢复启动；资源文件本体绝不进入数据库。
27. 实现名称、受管路径、标签及文件类型、大小、创建/修改时间等基础元数据查询，支持标签 AND、OR、NOT，并提供正确的最近项目和常用标签；首版不读取正文或建立全文索引。
28. 提供四个统一入口：系统全局 Quick Tag、Explorer 右键、TAGTAG 主窗口拖入，以及用户可选开启的悬浮球拖入。
29. 未受管资源从任一入口进入时，在同一个“导入并标注”窗口展示目标资源、复制/移动选择和标签选择；允许零标签确认并进入待整理区，取消时不导入，不使用二段窗口。
30. 已受管资源再次从 Explorer、主窗口或悬浮球进入时，不重复导入，只进入标签选择；无法可靠取得目标时打开空面板，绝不静默使用上次对象或剪贴板。
31. 悬浮球只作为可配置入口，拖入后打开同一确认窗口，不因拖放动作自动提交导入。
32. 全局备份包含数据库、全部受管资源、操作日志、清单和校验信息，用于完整灾难恢复。
33. 空间导出包包含单个空间的标签、查询、历史、资源清单及其引用资源内容；同一受管实体即使被多个标签引用也只打包一次，不按内容合并不同受管实体；导入时按稳定资源 ID 识别同一实体。
34. 只包含标签结构等配置、不包含资源内容的导出定义为空间模板，不称为备份。

### P1：在核心稳定后增加

1. [已实现于 v0.7.0] 文件夹标签继承及继承来源解释。
2. 保存查询、固定/隐藏常用标签、历史清理。
3. 更复杂的自动命名和归档规则。

### 明确暂缓

文件预览、独立的物理整理功能、实时多机协作、自动规则移动、插件系统、AI 标签建议和全文提取不进入当前范围。

## 6. 必须由用户确认的高影响问题

已确认：整个应用只有一个全局存储根；标签空间只隔离标签、查询和历史，并可引用同一个受管实体。复制导入后不再跟踪或同步外部源资源，存储根内版本是唯一受管版本。默认保留原文件名，标签不改名；名称冲突按操作系统的同一父目录规则判断，不同文件夹允许同名。恢复先前路径时只在目标空闲时直接执行；同名冲突绝不自动覆盖，只能重命名后放回、改到其他位置或取消。正常内容修改不告警；外部改名/移动由用户接受新路径或恢复记录路径；外部删除保留为缺失资源，直到重新定位或清除记录。全局备份负责完整灾难恢复；空间导出包自包含该空间引用的资源，同一受管实体只打包一次；无资源内容的标签配置称为空间模板。新建标签默认不唯一；显式复用才形成唯一标签的共享实体，已有标签只能通过可预览、可撤销的合并或拆分改变关系。文件夹标签默认只标文件夹；显式子项继承是动态有效标签，批量直接标注是独立固定操作。全局快捷键、Explorer 右键、主窗口拖入和可选悬浮球拖入统一进入同一个导入并标注流程；允许零标签确认并进入待整理区，取消才表示不导入。空间成员关系独立于标签；未标注按空间计算，并提供所有空间均无有效标签的全局待整理视图。导入窗口同时选择存储根内目标目录，文件夹保留完整内部层级，标签层级不改变物理目录。首版使用存储根内持久的 Windows 普通文件，用户可直接编辑，不采用临时工作副本、虚拟磁盘或虚拟文件系统；每个受管实体对应一个具体路径，其他组织位置以索引为主，必要时使用快捷方式或链接。首版明确不实现全局内容寻址、透明去重、内容对象共享或写时复制，不同路径的同内容文件仍是不同受管实体。首版检索名称、受管路径、标签和基础元数据，支持标签布尔组合，但不读取文件正文或建立全文索引。删除普通标签位置只改变层级位置，子位置默认提升，其他位置和资源标注保留；最后一个位置转入标签实体删除确认，删除子树是独立命令。删除标签实体会删除当前空间中的全部位置、直接标注和继承规则，提升子位置但不触碰资源文件或空间成员关系；失去最后一个有效标签的资源进入空间待整理区。技术路线继续使用 Flutter，Windows 系统能力通过最小原生桥接实现，Explorer Shell 扩展保持为独立小组件，不迁移到 .NET UI 技术栈。

首个里程碑已确认先完成存储根、真实导入、SQLite 元数据、监控、日志、撤销与基础备份；系统热键、Explorer 右键、悬浮球和托盘属于里程碑 2。SQLite 仅用于元数据和索引，资源文件本体始终是存储根中的原始、未加密普通文件。

## 7. 原型阶段的实现风险（历史快照）

- 首次启动自动载入 demo 数据，可能被误认成真实文件。
- “打开资源”只记录事件，不会打开文件；“修改时间”也是添加记录时间。
- 最近列表没有按最近事件时间排序。
- JSON 保存不是原子替换，保存失败时 UI 已先显示新状态。
- JSON 虽写入版本号，读取时不校验版本或引用完整性。
- 标签实体删除、位置移动/排序、资源编辑/删除、空间编辑/删除都缺失。
- 方案文档的直接/继承标签、软删除和操作日志尚未进入模型。
- 当前模型允许保存任意外部路径，没有“必须初始化存储根”“导入模式”“唯一受管实体”或导入日志，和已校正需求存在结构性偏差。
- 既有产品方案以原地索引为默认，需要在需求确认后修订，不能直接作为下一阶段实现依据。
- 当前 UI 没有待整理区，也没有区分合法未标注资源和数据库缺失记录的孤立内容。
- 当前实现没有存储根监控、孤立内容接管、缺失资源状态或一致性告警处理流程。
- 当前标注与筛选统一绑定 `placementId`；这会让唯一标签的不同位置产生不同结果，与已确认语义冲突。首期数据模型必须同时支持实体级共享结果和独立同名实体隔离。
- 当前模型没有子项继承规则、直接/继承来源区分或动态有效标签计算。
- 当前 Quick Tag 只处理应用内已选资源，没有系统级快捷键、Explorer 选择获取、文件拖入、统一导入确认窗口或悬浮球入口。
- 当前 `TagResource` 直接保存路径与新确认的一实体一路径方向一致，但 JSON 存储仍没有路径唯一性约束、事务、真实文件操作、操作日志或撤销能力，不能直接作为正式存储实现。
- 现有 4 个测试不足以保护文件系统、存储迁移和 Windows 集成。
